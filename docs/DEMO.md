# 3 分钟演示脚本

> 目标：评委在 3 分钟内看懂「通知 → 活动 → 冲突 → 替代时段」。
> 先保证主线，再展示拍照课表和提醒。

## 0. 演示前 5 分钟检查

```powershell
cd ea-hackathon
node server/server.js
```

- 打开 <http://127.0.0.1:3000>，确认活动列表能加载
- 微信开发者工具打开 `miniprogram/`，`Ctrl+B` 编译
- 确认「详情 → 本地设置 → 不校验合法域名」已勾选

### 演示数据

后台保留：

- 校园寻景，次元同游（11-10 19:45-21:00）
- 摄影分享会（11-11 19:30-21:30）
- 人工智能前沿讲座（11-06 15:00-17:00）

如果「校园寻景」已存在，演示时用「人工智能前沿讲座」或先删除再重新导入，避免重复。

### 预置冲突日程

在小程序「日程 → 课程日程」添加：

```text
名称：高数补习
日期：2026-11-10
开始节次：第 7 节
结束节次：第 8 节
开始：19:30
结束：20:30
```

这样和「校园寻景」19:45-21:00 重叠，报名时会被拦截。

## 1. 时间轴

### 0:00-0:20 痛点

> 社团通知发在 QQ 群里，学生看到时已经和课表撞了；报名后才发现去不了，也没有替代场次。校园管家把通知变成活动，在报名那一刻就拦截冲突。

### 0:20-0:50 后台导入

1. 打开 <http://127.0.0.1:3000>
2. 「来源」选 **QQ 群消息**（说明：真实 QQ 机器人走同一个 `/api/qq/event`，本机注入被拦截，演示用同一入口模拟）
3. 粘贴下面这段：

```text
📣活动主题
“校园寻景，次元同游”
⏰️报名时间。
2026年11月4日晚上21：30～22：00
📍活动地点：
师生活动中心（春兰居）
🕰活动时间：
2026年11月10日19：45～21：00
🔥主办方：
动漫协会
2、按时提交作品可获得二课美育分4分。
```

4. 粘贴后会自动解析，指出：
   - 活动时间：11-10 19:45-21:00
   - 报名时间：11-04 21:30-22:00
   - 地点 / 主办方 / 类型
5. 点「导入」

### 0:50-1:20 小程序列表

1. 首页刷新，出现「校园寻景，次元同游」
2. 搜索「校园」或点「文体活动」
3. 可点「避开冲突」演示过滤：有高数补习时该活动会被隐藏，再点恢复

### 1:20-2:00 报名冲突

1. 进「校园寻景」详情
2. 点「报名」
3. 弹窗：

```text
时间冲突
与「高数补习」冲突
冲突时间：2026-11-10 19:30 - 20:30
可以去的时段：
...
```

4. 点「知道了」
5. 说明：首尾相接不算冲突；替代时段来自最近 7 天的空闲窗口

### 2:00-2:30 日程分栏

1. 底部「日程」
2. 「课程日程」：高数补习
3. 「活动日程」：已报名活动（如果有）
4. 说明两者一起参与冲突检测，取消报名会一起移除

### 2:30-3:00 拍照课表 + 我的

1. 日程 → 「拍照 / 选图」→ 选课表截图
2. 弹窗显示「自动定位：周一 · 第1-2节」等
3. 指出：网格横线 + 彩色块定位，未确认不能导入
4. 切「我的」：已报名 + 学分饼图

> 如果时间不够，拍照课表只展示弹窗，不实际导入。

## 2. 备用话术

### 如果替代时段为空

> 当前日程比较少，系统没有找到 7 天内的合适空档；真实使用中课表越完整，推荐越准。

### 如果 OCR 识别错

> OCR 只负责文字，网格负责定位；起止节次需要人工确认，这是故意的防误导入设计。

### 如果被问真实 QQ

> OneBot 适配器、去重、解析入库已经完成，并已用模拟群消息验证；本机 QQ 注入被客户端拦截，所以现场用同一 `/api/qq/event` 入口演示，不伪造真实登录。

---

## 3. 不要做的事

- 不要现场安装 QQ/NapCat
- 不要现场等 10 分钟提醒；提醒功能只说明，或提前把报名时间设成当前 +5 分钟
- 不要打开多个后端/多个小程序实例
- 不要把 `server/data.json` 里的运行时数据当提交物
