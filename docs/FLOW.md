## 1 三条工作规则

1. **一次只做一个工序**，做完跑验收、提交一次，再进下一个
2. **每个工序结束必须验收**，不能「写完就算完成」
3. **不越界**：功能范围见 `AGENTS.md` 第 1 节，不加徽章、不做学分统计、不写 QQ 代码

## 2 工序单

### P2.5 静态检查器（10 分钟）

**为什么先做**：后面要写 4 个页面，它能在 3 秒内抓出「bindtap 拼错」「组件没声明」「用了 datetime-local」这类查半小时的错。

**产出**：`tools/check-miniprogram.js`

**验收**：
```bash
node tools/check-miniprogram.js ./miniprogram
```
输出每个页面的检查结果，无 ERROR。

---

### P3 管理后台（2.5 小时）★ 优先做，它是「写」的一端

**产出**：
```
server/public/index.html    表格 + 表单
server/public/app.js        调接口
server/public/style.css
```

**页面要有四块**：
1. **粘贴框** — textarea，粘通知原文
2. **解析结果** — 点「解析」后调 `POST /api/parse`（若无此接口则由前端直接展示服务端 import 前的预览），字段可编辑
3. **活动列表** — 表格：标题、时间、地点、学分、类型、来源（`source`）��操作列
4. **操作** — 导入、编辑、删除

**接口现状**（已逐条核对 `server/server.js`）：

| 接口 | 状态 |
|---|---|
| `GET /api/health` | ✅ 已有 |
| `GET /api/activities` → `{ ok, activities }` | ✅ 已有 |
| `POST /api/import` `{ text, source }` → 201 | ✅ 已有 |
| `PUT /api/activities/:id` | ❌ **本工序要加** |
| `DELETE /api/activities/:id` | ❌ **本工序要加** |

> ⚠️ 响应包了一层：`{ ok: true, activities: [...] }`，不是裸数组。
> `utils/request.js` 必须拆开，否则页面拿到的是对象而不是列表。
> 另外 `POST /api/import` 失败会返回 **422**（解析不出来时），前端要处理这个码。

**验收**：
```bash
node server/server.js
# 浏览器打开 http://127.0.0.1:3000
```
- [ ] 粘一段通知 → 解析出标题/时间/地点/学分
- [ ] 点导入 → 表格里出现这条
- [ ] 编辑能保存，删除能去掉
- [ ] `server/data.json` 里真的变了

**注意**：表单里的时间用 `<input type="datetime-local">`（网页可以用，小程序不行）。

### P5 列表 + 搜索 + 类型筛选（2 小时）★ 演示主线第 2 步

**产出**：`pages/index/*`

**要求**：
- `onLoad` 调 `utils/request.js` 拉 `/api/activities`
- 顶部搜索框（标题/地点模糊匹配）
- 类型筛选：全部 / 学术科技 / 志愿公益 / 文体活动 / 技能特长
- 卡片：标题、时间、地点 ↓ 点击进详情
- **空态**（没数据时提示）+ **错误态**（后端挂了显示「网络异常」并回退本地）
- **不加冲突徽章**（冲突只在报名时算）

**验收**：
- [ ] 后端开着 → 看到活动
- [ ] 搜索「讲座」能过滤
- [ ] 切换类型能过滤
- [ ] **关掉后端** → 显示错误提示，不白屏

### P6 详情 + 报名拦截 + 替代时段（3 小时）★ 演示主线第 3、4 步，最高光

**产出**：`pages/detail/*`

**要求**：
- 接收 `id`，拉单条数据（或从上一页传）
- 展示标题、时间、地点、学分、类型、主办方
- 「报名」按钮 → 读本地日程 → `conflict.check()` → `conflict.suggestSlots()`
- 冲突时 `wx.showModal` 显示：与「高数补习」冲突 + **推荐时段**
- 不冲突 → 报名成功提示

**验收**：
- [ ] 日程里加「周五 15:00-17:00 高数补习」
- [ ] 点冲突活动的报名 → 弹窗拦截 + 给出替代时段
- [ ] 点不冲突的活动 → 报名成功
- [ ] **首尾相接不算冲突**（14:00-16:00 与 16:00-18:00）
