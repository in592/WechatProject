# AI 使用说明

## 1. 使用的工具

- **DeepSeek Harness（DSH）**，模型 `deepseek-flash`
- 使用时间：2026-11-03 至 2026-11-04 赛时窗口内
- 交互方式：在本地工作区中由 AI Agent 直接读写项目文件、运行命令、跑测试

没有使用其他代码生成服务，没有把 API Key、Token、真实账号密码交给模型。

---

## 2. AI 做了什么

| 范围 | 具体内容 |
|---|---|
| 工程脚手架 | 小程序五页四件套、`app.json`、`app.wxss`、零依赖 Node 服务 |
| 算法 | `utils/conflict.js` 重叠 + 替代时段；`utils/parser.js` 通知解析；自测脚本 |
| 小程序 | 登录、列表/搜索/类型筛选、详情/报名、日程分栏、我的/报名列表 |
| 管理后台 | 导入/解析/编辑/删除、粘贴自动识别、报名时间字段 |
| OCR | Windows 本机 OCR、网格横线检测、彩色课程块跨节次、批量确认弹窗 |
| QQ 适配 | OneBot 11 `/api/qq/event` 接收、CQ 码清理、去重、来源标记 |
| 提醒 | 前台 T-10 检查、关注/已报名两类提醒、本地去重 |
| 文档 | README、演示脚本、提交清单、本说明 |

## 3. 人做了什么

- 确定产品方向：活动通知 → 冲突拦截 → 替代时段
- 确定功能范围与取舍：不做列表冲突徽章、不做云端、只做本机
- 确定 UI 方向 D（樱粉 × 薄荷青 × 浆果红）
- 提供真实活动通知、课表截图和时间规则
- 选择技术方案：OCR 先手动确认，后升级网格/色块识别；QQ 先适配器、后尝试真实登录
- 在开发者工具中实际点击、截图、反馈问题
- 审核 AI 生成的代码和文案，决定是否保留

## 4. AI 没有做什么

- 没有伪造真实用户、真实活动或真实聊天记录
- 没有提交任何 API Key、Token、QQ 账号密码
- 没有实现真实 QQ 登录：本机 QQ 注入被客户端拦截，最终使用同一 `/api/qq/event` 入口做模拟上报
- 没有替代人工做最终验收：小程序页面、Canvas 饼图、OCR 实际图片仍由人点击确认

## 5. 关键迭代记录（可复核）

1. 先做纯函数 `conflict.js` / `parser.js`，用 `tools/selftest.js` 锁定行为
2. 做静态检查器，拦截 `bindtap` 拼错、`setData` 未初始化等问题
3. 管理后台先支持粘贴解析，再补「粘贴自动识别」
4. OCR 从只识别文字，升级为：
   - OCR 返回文字坐标
   - 横向网格线检测
   - 彩色课程块上下边界
   - 未确认节次禁止导入
5. QQ 适配器先完成 `/api/qq/event` 模拟验证，再尝试 NapCat；本机注入失败后停止，不把失败包装成成功

## 6. 可复核方式

```powershell
git log --oneline
node tools/selftest.js
node tools/check-miniprogram.js ./miniprogram
```

- 46 项算法自测
- 5 个页面静态检查，`ERROR 0`
- 所有提交在赛时窗口内，Git 历史可查
- 运行时数据 `server/data.json` 已 gitignore，不提交

## 7. 局限

AI 生成代码需要人工验证。本项目仍存在：

- 真实 QQ 登录未打通（环境限制）
- 拍照 OCR 依赖 Windows 和彩色课表，跨节次仍需人工确认
- 前台提醒无法覆盖小程序退出场景

这些限制已在 README 和演示脚本中明确写出，没有隐藏。
